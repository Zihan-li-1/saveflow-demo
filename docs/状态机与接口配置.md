# SaveFlow 前端状态机与接口配置

2026-09-22 B 更新：新增 [Banking Core 公共底座](Banking-Core.md)。旧 Mock 的操作记录、数据读取及执行/待核实状态已接入公共模块；转账使用独立的精确预览与确认协议。下文 v1 仅描述旧储蓄计划兼容接口。

更新：已新增独立的 Qwen 模型接口 `/api/agent`，以及 `clarifying`（追问）和 `answered`（回答完成）状态。自然语言理解现可通过 Qwen 完成，模型调用配置、数据发送范围与部署方法见 [Qwen接入与部署](Qwen接入与部署.md)。本文其他“尚未接入模型”的描述为最初 Mock 版本背景；业务创建/支付依然使用模拟接口。

## 适用范围与依据

业务依据为项目根目录《SaveFlow-个人消费与财富管理系统.md》，重点落实“分析 → 方案 → 用户确认 → 执行 → 反馈”及关键操作前确认。

本项目未提供微众银行内部前端规范、合作方接口协议或准入材料。本实现参考微众公开的授权、个人信息保护要求，采用可审查的金融业务交互设计；**不是微众官方标准、官方 SDK、银行接口接入或合规认证**。下述状态名、字段、错误码、幂等协议均为 SaveFlow 自定义约定。公开参考：[微众银行隐私政策 V2.4 更新公告](https://w.webank.com/mbwebsite/manuscript/privacyPolicyV2.4.html)。该来源支持授权与个人信息保护原则，不构成状态机/API 协议的来源。

## 已实现的前端流程

核心实现：`src/lib/flow-machine.ts`（纯状态机）、`src/lib/use-saveflow.ts`（副作用与 UI 控制）、`src/lib/api/`（契约、配置、客户端、Mock）。首页已接入这些模块。旧版卡片调试页、消费即储蓄组件和静态发布产物已移除。

| 当前状态 | 允许事件 | 下一状态 / 行为 |
| --- | --- | --- |
| welcome 等待目标 | START | 勾选模拟账单分析授权后进入 analyzing |
| analyzing 分析中 | ANALYZED / FAILED | plan / error；失败只能重新分析 |
| plan 待确认 | EDIT / CONFIRM / CANCEL | edit / executing / cancelled |
| edit 修改草稿 | SAVE / CANCEL | 校验后回到 plan，必须重新确认 / cancelled |
| executing 提交中 | SUCCEEDED / FAILED / UNCERTAIN | success / error / unknown |
| unknown 结果待核实 | CHECK | checking；禁用创建、重置、取消 |
| checking 查询中 | SUCCEEDED / FAILED / UNCERTAIN | success / error / unknown |
| error 明确失败 | START 或 EDIT | 按失败阶段恢复，不能直接重放写操作 |
| success / cancelled | START / RESET | 新分析 / welcome |

非法事件保持原状态；同步 ref 门禁阻止同一帧内重复点击。只读请求可重置取消，并通过请求代次丢弃过期响应。写操作不自动重试；网络错误、超时、5xx、格式错误和不匹配回执均保守地进入 unknown。只有确定的前置拒绝或最终失败回执才允许修改后重新确认。

HTTP 模式提交前将不透明操作编号写入当前标签页的 `sessionStorage`；刷新后恢复待核实状态，只能查询该编号。目标文本、金额和凭证不写入浏览器持久存储。此机制不覆盖关闭标签页后的恢复、跨设备或多标签并发，生产系统必须提供服务端操作列表与持久化账务查询。Mock 记录仅在内存中，刷新即重置，不用于真实业务。

首页“确认创建计划”仅调用 `create-plan`，不会调用支付接口；创建计划不会增加已储蓄金额。右侧目标、收入和进度统一取公共仓库中的合成数据，自然语言目标解析、真实账户变动、支付界面、订阅管理与理财适当性评估尚未实现。旧版消费支付场景和兼容契约已删除，后续风险场景应按具体 Banking Skill 独立建模。

## 环境配置

复制根目录 `.env.example` 为 `.env.local`，修改后重启开发服务；静态部署需重新构建。

| 变量 | 默认 | 约束 |
| --- | --- | --- |
| NEXT_PUBLIC_SAVEFLOW_API_MODE | mock | mock / http；错误值启动时报错 |
| NEXT_PUBLIC_SAVEFLOW_API_BASE_URL | 空 | HTTP 服务根地址，不含 `/api/saveflow`；远程 HTTPS，本机 localhost / 127.0.0.1 可 HTTP |
| NEXT_PUBLIC_SAVEFLOW_API_TIMEOUT_MS | 10000 | 500–60000 毫秒 |

默认 Mock 完全在浏览器使用合成数据，支持草稿确认、幂等回执和结果查询。本项目已提供 Mock HTTP 处理器；运行 `npm run dev:qwen`，设置 mode=http、base URL 留空，并传演示访问码即可同源联调。外部真实沙箱仍需另行实现。

项目保留 `output: "export"`。`out/` 没有 POST 服务能力；`/api/saveflow` 的 GET 仅导出固定合成数据快照。本地自定义服务和完整项目的 Netlify Function 已提供旧 POST `/api/saveflow` 适配器；仅上传 out 不会包含处理器。仅设置 mode=http、启动 next dev 不会产生业务 POST 接口。

`NEXT_PUBLIC_*` 编译进入浏览器包，严禁填入银行密钥、证书、访问令牌或真实身份信息。联调失败不会静默回退 Mock。

## 接口契约 v1（SaveFlow 自定义）

统一 `POST {baseUrl}/api/saveflow`，`Content-Type: application/json`。所有请求带 `X-Request-ID`；写请求额外带 `Idempotency-Key`，该值同时作为 `operationId`。每次查询有独立请求编号，查询体携带原操作编号。金额传整数分（Fen），百分比传基点（Bps，1000 = 10%）；展示时转换为元和百分比。

| action | 请求字段 | data |
| --- | --- | --- |
| analyze | goal: 1–500 字；consent: true | totalExpenseFen: 非负整数；subscriptionCount: 非负整数 |
| create-plan | monthlySavingFen: 1–300000；saveRateBps: 0–10000；confirmed: true | 操作回执 |
| operation-status | operationId: 原幂等键 | 操作回执；未取得结果返回 pending，不能推断失败 |

`create-plan` 的 3000 元上限是本 Demo 页面规则，不是银行通用限额。Mock 必须同样检查授权、确认、数值和 action 白名单。幂等键相同且参数相同返回原回执；参数不同拒绝为 `IDEMPOTENCY_CONFLICT`。公共 OperationStore 内存存储不提供跨进程保障，服务端必须按已认证用户 + action + 幂等键持久化并原子执行，不能依赖前端按钮禁用防重。

请求示例（用户明确确认之后）：

```json
{
  "action": "create-plan",
  "monthlySavingFen": 250000,
  "saveRateBps": 1000,
  "confirmed": true
}
```

响应示例：

```json
{
  "code": "OK",
  "message": "请求成功",
  "requestId": "本次请求编号",
  "data": {
    "operationId": "原 Idempotency-Key",
    "status": "succeeded",
    "message": "计划已创建；本次未发起支付"
  }
}
```

HTTP 2xx 不等于业务成功。客户端检查 envelope、字段、最终状态及操作编号。`status` 仅允许 succeeded / failed / pending；业务拒绝可返回 `code: OK` + failed 回执。分析页使用接口结果，成功文案使用回执内容。错误 envelope 保持 code、message、requestId 字段。

| 错误码 | 语义与处理 |
| --- | --- |
| VALIDATION_ERROR / CONFIRMATION_REQUIRED | 执行前校验拒绝，修改并重新确认 |
| UNAUTHORIZED / FORBIDDEN | 未执行，提示会话或权限问题；登录由接入方完成 |
| INSUFFICIENT_BALANCE / LIMIT_EXCEEDED | 确定未执行；前端允许调整 |
| IDEMPOTENCY_CONFLICT | 原操作可能已执行；先查询，禁止换键盲目重试 |
| TIMEOUT / NETWORK_ERROR / INVALID_RESPONSE / 其他服务端错误 | 写操作结果未知，查询原编号 |

BFF 不得在可能已执行后返回上述“执行前拒绝”码。查询失败继续待核实，不显示“未扣款”。请求不自动重试，用户可以再次查询；生产环境可增加有上限的只读轮询。

## 后续模块的状态与接口约定（未实现）

| 模块 | 建议状态 | 建议服务边界 |
| --- | --- | --- |
| 账单导入 / 分类 | 待授权 → 上传 → 解析 → 待确认 → 已入账；失败可重试 | 导入任务、任务查询、分类草稿、分类确认 |
| 虚拟卡 / 规则 | 草稿 → 待确认 → 提交中 → 生效 / 拒绝 / 待核实 | 规则预览、带版本的规则更新、冻结/解冻、操作查询 |
| 消费与储蓄 | 预检 → 待确认 → 提交 → 成功 / 失败 / 待核实；余额不足暂停 | 支付报价、确认授权、原子账务/补偿、分录与支付查询 |
| 自动储蓄 | 启用 ↔ 手动暂停；余额不足 → 自动暂停 → 用户确认恢复 | 暂停、恢复、额度与月度上限校验 |
| 订阅 | 识别 → 用户确认 → 管理；冻结/取消需独立确认 | 订阅列表、续费提醒、冻结与取消操作查询 |
| 目标与理财 | 目标草稿 → 生效 → 达成；理财仅建议、风险评估后再进入交易 | 目标进度、报告、风险评估、产品适当性与披露 |

这些扩展不应伪装为已接通接口。当前 `create-plan` 仅支持固定合成数据，不具备真实报价、商户订单、授权凭证、双分录或扣款能力，不能直接用于银行支付。

## 后端接入责任与验收

真实银行接入需要银行合作方协议及沙箱资料。BFF 负责身份认证、HttpOnly/Secure 会话 Cookie、CSRF/Origin 校验、精确 CORS 允许源（credentials 模式禁止 `*`）、用户资源权限、服务端参数校验、风控、幂等持久化、账务一致性、审计脱敏以及服务端密钥/签名。前端的 confirmed 布尔值不是资金授权凭证；本 Demo 的授权勾选也不构成正式隐私授权书。

回归命令：`npm test`、`npm run typecheck`、`npm run lint`、`npm run build`。浏览器验收：未授权不能开始；修改后须确认；连续点击仅提交一次；失败后按阶段恢复；超时后只能查询；HTTP 刷新恢复原编号；取消不创建计划；创建计划不增加已储蓄余额。`tests/flow.test.cjs` 覆盖状态边界、参数校验、幂等冲突、超时查询、HTTP 错误和回执匹配。
